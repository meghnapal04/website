Data lineage

From ECB to this page

Each build runs the same six stages. You can trace a published value back through every stage to the exact ECB series and download it came from.

1 · INGEST

ECB Data Portal API

11 series, downloaded as CSV. Raw response stored unchanged with SHA-256 hash and UTC fetch time.

→↓

2 · STANDARDISE

rates_long.csv

One row per observation: date, field, value, unit, frequency, ECB series key. Rules T1–T2.

→↓

3 · TRANSFORM

Calendar & derived fields

Aligned to TARGET2 business days, monthly view, spreads in bp. Rules T3–T4.

4 · VALIDATE

Quality gate

8 checks. ERROR values are withheld, WARN values are flagged. Rule T5.

→↓

5 · PUBLISH

CSVs + manifest.json

Published files, data-quality log, data dictionary, and a manifest of hashes for every input and output. Rule T6.

→↓

6 · BACKTEST

Check performance

Known errors are injected into real history to measure what the checks catch.

Method & limits

Read before using

Why a yield curve instead of swap rates. Official daily euro swap rates (such as the ICE Swap Rate) and daily EURIBOR fixings are licensed data and cannot be republished. This lab uses only data the ECB allows to be reused: the euro area AAA government curve stands in for the term structure, and EURIBOR appears as the ECB's monthly averages.

Reference date vs publication date. €STR for a business day is published at 08:00 CET on the next TARGET2 business day. Dates in this dataset are reference dates.

What the checks cannot do. They test whether a value is plausible, not whether it is true. The backtest shows small one-day errors of a few basis points are mostly not caught. Catching those would need a second, independent source.

Reproduce it. The pipeline is plain Python (pandas). Running python rates/pipeline/build.py downloads the data again, rebuilds every file and writes a new manifest. The code is in the repository.
